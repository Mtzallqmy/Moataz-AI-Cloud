# Moataz AI Android ↔ Moataz AI Cloud Integration

This document is the versioned integration contract. Android code remains in `moataz-ai-android`; this repository only implements the cloud side.

## Base URL

Production API: `https://api.moataz.ai/api/v1`

During Preview/Development use the assigned Vercel URL, preserving `/api/v1`.

## Authentication and session handling

Android authenticates with Supabase Auth using the project's public/publishable key. A successful login yields an access token (JWT), refresh token and expiry. For each protected Moataz Cloud request send:

```http
Authorization: Bearer <supabase_access_token>
Content-Type: application/json
```

The API validates the JWT against Supabase Auth and checks account status. Never send the refresh token to Moataz Cloud endpoints; use it only with Supabase Auth to refresh the session. Refresh shortly before expiry or after an `AUTH_REQUIRED` response when the refresh token remains valid.

Logout: call Supabase Auth sign-out on Android, delete locally persisted access/refresh tokens, and clear user-specific cached cloud data.

## Remote config

### GET `/config`

Authentication: none.

Example response:

```json
{"config":{"minimum_supported_app_version":"1.0.0","maintenance_mode":false,"global_notices":[],"enabled_cloud_features":["managed_chat","cloud_sync","uploads"],"upload_limits":{"images":20971520}}}
```

No secret will ever be placed in this response.

## User dashboard

### GET `/dashboard`

Authentication: Bearer JWT.

Returns account, plan, quota/usage, storage and enabled managed providers in one request.

```json
{"account":{"id":"uuid","email":"user@example.com","status":"active"},"plan":{"id":"uuid","slug":"free","name":"Moataz Free"},"quota":{"daily_tokens":1200,"monthly_tokens":9000,"daily_requests":4,"monthly_requests":31,"storage_bytes":2048},"usage":{"daily_tokens":1200,"monthly_tokens":9000,"daily_requests":4,"monthly_requests":31,"storage_bytes":2048},"storage":{"bytes_used":2048},"providers":[]}
```

### GET `/me`

Returns identity/profile, current plan, account status and quota summary.

### GET `/usage`

Returns daily/monthly token counts, request counts and tracked attachment bytes.

## Providers and models

### GET `/providers`

Returns only enabled managed providers allowed for the user's plan. Provider credentials and secret references are omitted.

### GET `/models?provider=<provider_uuid>`

Returns enabled models, optionally filtered by provider, including capability labels such as `text`, `vision`, `tools`, `streaming`, `audio`, `reasoning`, `structured_output`.

Android should use returned IDs, not hard-code database UUIDs.

## Managed chat

### POST `/chat`

```json
{"provider_id":"provider-uuid","model_id":"model-uuid","messages":[{"role":"user","content":"Hello"}],"temperature":0.7,"max_tokens":1024,"conversation_id":"optional-cloud-conversation-uuid"}
```

Flow enforced on the server: authentication → account → plan → provider/model status → quota/rate limit → credential selection/failover → provider call → actual usage accounting.

Response is the provider's normalized OpenAI-compatible chat-completion JSON. Android never receives a managed API key.

## Streaming

### POST `/chat/stream`

Use the same body (without `conversation_id` in the current streaming contract). Response is `text/event-stream`. Consume SSE chunks incrementally and stop at the provider's `[DONE]` event.

Android networking must disable response buffering and read the body as a stream. Cancellation closes the stream and records the managed usage event as failed/cancelled.

## Files

### POST `/files/upload-url`

Authentication: Bearer JWT.

Request:

```json
{"bucket":"images","conversation_id":"optional-uuid","filename":"photo.jpg","size_bytes":123456}
```

Response:

```json
{"bucket":"images","path":"<user_uuid>/<conversation_or_general>/<uuid>-photo.jpg","token":"signed-upload-token","signed_url":"https://..."}
```

Upload bytes directly to the returned Supabase signed URL. The path is generated by the server; do not invent another user's prefix. Private download URLs should be requested through a future download-signing endpoint rather than made public.

## Conversations / optional cloud sync

A conversation can remain local-only by never creating it in Moataz Cloud.

- `GET /conversations` — list synced conversations.
- `POST /conversations` — create a cloud-synced conversation.
- `GET /conversations/:id` — fetch owned conversation and messages.
- `DELETE /conversations/:id` — delete owned cloud conversation and cascading messages.

Create request:

```json
{"title":"Trip ideas","sync_enabled":true}
```

The server always scopes operations to the authenticated user.

## BYOK

BYOK is a separate Android mode:

```text
Android → user's provider directly
```

Managed mode is:

```text
Android → Moataz Cloud → managed provider
```

Only managed mode consumes Moataz Cloud AI quota in the current contract.

## Error contract

All Moataz Cloud errors use:

```json
{"error":{"code":"QUOTA_EXCEEDED","message":"Quota exceeded","details":{}}}
```

Handle at least: `AUTH_REQUIRED`, `ACCOUNT_DISABLED`, `PROVIDER_DISABLED`, `MODEL_DISABLED`, `PLAN_REQUIRED`, `QUOTA_EXCEEDED`, `RATE_LIMITED`, `STORAGE_LIMIT`, `PROVIDER_ERROR`, `INTERNAL_ERROR`, `VALIDATION_ERROR`, `NOT_FOUND`, `FORBIDDEN`.

Do not parse human-readable `message` to make application decisions; use `code`.

## Token refresh sequence

1. Read current session.
2. If access token is still valid, call Moataz Cloud.
3. If near expiry, refresh with Supabase Auth.
4. Replace locally persisted tokens atomically.
5. Retry a failed cloud request once after a successful refresh when the error was `AUTH_REQUIRED`.
6. If refresh fails, sign out locally and return to login.

Never log access tokens, refresh tokens, signed upload tokens or BYOK keys.
